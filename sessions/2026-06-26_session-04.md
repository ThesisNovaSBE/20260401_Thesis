### 1. Diagnosed and fixed the Stage 2 segfault (root cause: stale synthetic cache)

The Stage 2 pipeline was segfaulting immediately after `[1/2] Fine-tuning...`. Through
progressive diagnostic instrumentation (`flush=True` prints at every step) we isolated:

- **Hypothesis A tested:** joblib.load the artifact BEFORE torch import → PASS (artifact fine)
- **Hypothesis B tested:** joblib.load AFTER torch import → PASS (no interaction)
- **Actual crash point:** inside `train_stage2()` at Step A (`joblib.load`) — which passed
  in isolation, meaning the segfault was actually one step earlier: at a **stale cached
  feature matrix** (`data/processed/features.csv`) built from synthetic data.

`load_feature_matrix` caches to CSV and reuses it on subsequent runs. The cache was generated
before `.env` was set up with the real MIMIC-IV paths, so it contained synthetic hadm_ids
(round numbers: 200000, etc.). Stage 2 tried to match these against real MIMIC-IV-Note
discharge notes → zero matches → crash.

**Fix:** delete `data/processed/features.csv` to force rebuild from real MIMIC-IV data.
This is now done automatically by `diagnose_stage2.py` at the start of every run.

### 3. Built a comprehensive end-to-end diagnostic script

Created `diagnose_stage2.py` — a single script that runs the complete pipeline from scratch:
- Stage 0: environment + path validation (all packages, MIMIC paths, Ollama)
- Stage 1: clears stale cache → builds feature matrix from real/synthetic → trains XGBoost
- Stage 2: loads notes → tokenizer → model → 4-step smoke test → inference sample
- Stage 3: generates one sample explanation with phi4-mini

Runs in ~5 min with the smoke test cap. Full training still requires `python setup_stage2.py`.
Verified working on synthetic data (Stage 2 skipped, Stage 3 PASS).
